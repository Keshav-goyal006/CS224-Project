Project Summary: Hardware Image Convolution Accelerator (Current)
=================================================================
Target Platform: Digilent Nexys A7-100T FPGA
Scope: Current implemented system state (CNN excluded)

1) System Architecture Overview
-------------------------------
This project implements a hardware-software co-design image processing SoC:
- A custom RV32IM-style pipelined RISC-V core handles control and data movement.
- A memory-mapped 5x5 RGB streaming accelerator performs convolution/filter operations.
- UART RX and UART TX provide image ingress/egress.
- Bootloader firmware loads image payloads into DMEM over UART before processing starts.
- VGA path displays processed pixels from VRAM.

2) Convolution Accelerator (Current Core)
-----------------------------------------
Active accelerator: stream_accel_5x5_rgb

Implemented architecture:
- 5x5 sliding window with four RGB line buffers.
- Runtime-selectable filter kernels via sw[3:0].
- Pipelined math datapath to improve timing and DSP inference.

Current filter/mode set in hardware:
- 0001: Gaussian blur
- 0010: Edge detect
- 0100: Sharpen
- 0011: Diagonal motion blur
- 0101: Unsharp mask
- 0110: Vertical Sobel
- 0111: Cross flare
- 1000: Morphological min mode (pipelined min-tree)
- default: Identity

Measured accelerator timing (simulation):
- push -> valid_mac: 3 cycles
- push -> final_pixel_reg: 4 cycles

DSP status:
- Current synthesis reports DSP48E1 usage across the design with strong DSP mapping in stream_accel_5x5_rgb due to the pipelined MAC structure.

3) Processor and Memory-Mapped Control
--------------------------------------
CPU datapath:
- 32-bit pipelined RISC-V with IF/ID, Execute, and WB/memory staging.
- Stall and forwarding/hazard-control logic are present in the pipeline implementation.

Memory-mapped control highlights:
- Accelerator push/read: 0x00012024 / 0x00012028
- UART TX data/status: 0x00015000 / 0x00015004
- UART RX data/ready: 0x00015008 / 0x0001500C
- Switch register: 0x00016000
- Warm-reset pending/clear: 0x00016010 / 0x00016014
- VRAM base: 0x00030000

4) UART_RX and Bootloader (Added to Report)
--------------------------------------------
UART_RX integration:
- uart_rx module uses synchronized sampling (double-register input).
- Receives start/data/stop bits and exposes byte-ready pulse.
- Connected to SoC interconnect as rx_data_in and rx_valid_in.

Bootloader flow:
- bootloader_main waits for SW[15]=1 (load mode).
- Receives 49152 bytes over UART RX.
- Stores payload at DMEM image base (0x00001000).
- Waits for SW[15]=0, then application processing phase runs.
- Warm reset handling is integrated so second-pass operation can preserve DMEM image data.

5) Physical Interaction and Runtime Behavior
--------------------------------------------
On-board controls:
- sw[3:0] selects active filter mode.
- sw[15] controls bootloader load vs run phase.
- LEDs are memory-mapped for status/debug indications.

Output paths:
- Processed pixels are written to VRAM for VGA display.
- RGB bytes are streamed via UART TX for capture/reconstruction on host tools.

6) Current Project Status
-------------------------
What is working now:
- Integrated bootloader + pipeline simulation flow passes end-to-end.
- Full image load, first run, warm reset, and second run complete successfully.
- Output pixel dumps and reconstructed images are generated in simulation.
- Accelerator pipeline latency has been measured and documented.

Current focus (practical next steps):
- Hardware bring-up validation on board for the same integrated flow.
- Tightening switch input conditioning/debouncing for robust real-board control behavior.
- Throughput optimization where UART becomes the system bottleneck in steady-state streaming.
